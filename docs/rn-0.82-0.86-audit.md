# React Native 0.82–0.86 Surface audit

This audit covers the Surface code and public contracts affected by the move from React Native 0.81.5 to 0.86.2. It uses the React Native release posts and changelogs for [0.82](https://reactnative.dev/blog/2025/10/08/react-native-0.82), [0.83](https://reactnative.dev/blog/2025/12/10/react-native-0.83), [0.84](https://reactnative.dev/blog/2026/02/11/react-native-0.84), [0.85](https://reactnative.dev/blog/2026/04/07/react-native-0.85), and [0.86](https://reactnative.dev/blog/2026/06/11/react-native-0.86).

## Release-by-release findings

| Release | Surface-relevant finding                                                                                                                                                                    | Outcome                                                                                                                                                                                                                             |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0.82    | New Architecture became the only runtime architecture. Host-component refs gained DOM-like APIs while retaining legacy measurement methods.                                                 | **VERIFIED: NO CHANGE REQUIRED** — Surface has no native modules or legacy-architecture branch. Its `measureInWindow` capability checks remain valid on Fabric refs and React Native Web nodes.                                     |
| 0.83    | React moved to 19.2 and React Native reported no user-facing breaking changes. Android networking/animation deprecations do not occur in Surface.                                           | **CHANGE REQUIRED** — development and consumer React assumptions now target React 19.2.3. Component behavior needs no semantic branch.                                                                                              |
| 0.84    | React synchronized to 19.2.3, Hermes V1 became default, more legacy native classes were removed, and Node 22 became the minimum.                                                            | **CHANGE REQUIRED** — compile with React 19.2.3 and Node 24 typings. **VERIFIED: NO CHANGE REQUIRED** for removed native classes because Surface is JavaScript/TypeScript-only.                                                     |
| 0.85    | `StyleSheet.absoluteFillObject` was removed, `Pressable` listener behavior in hidden `Activity` changed, TypeScript utility types changed, and Metro moved to 0.84.                         | **VERIFIED: NO CHANGE REQUIRED** — Surface does not use `absoluteFillObject`, `Activity`, internal RN types, the RN Jest preset, or custom Metro configuration. TypeScript 6 compilation validates the public RN types it does use. |
| 0.86    | Android edge-to-edge fixes corrected `measureInWindow`; Yoga/rendering fixes landed; `Pressable.android_ripple` widened; Metro moved to 0.84.2; there were no user-facing breaking changes. | **CHANGE REQUIRED** — safe-area compatibility now targets 5.7.x and measurement assumptions are documented against corrected edge-to-edge coordinates. No offset workaround or platform fork is needed.                             |

## Required area decisions

| Audit area                           | Decision                         | Evidence and action                                                                                                                                                                                                                                             |
| ------------------------------------ | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Removed/deprecated APIs              | **VERIFIED: NO CHANGE REQUIRED** | No removed `StyleSheet.absoluteFillObject`, legacy native class, deprecated networking interceptor, `ViewUtil`, or AppRegistry instrumentation API is imported.                                                                                                 |
| TypeScript types                     | **CHANGE REQUIRED**              | TypeScript is `6.0.3`; React/RN declarations are validated with React 19.2 and RN 0.86.2. No deep React Native imports, `any`, or migration suppressions are used.                                                                                              |
| Fabric / New Architecture behavior   | **VERIFIED: NO CHANGE REQUIRED** | Surface contains no native module, UIManager-type switch, bridge path, or legacy-architecture feature flag. Standard host components and refs are Fabric-compatible.                                                                                            |
| Layout and measurement               | **VERIFIED: NO CHANGE REQUIRED** | Grid/Container layout uses public Flexbox/View styles. Menu and Tooltip capability-check `measureInWindow`; RN 0.86 fixes its edge-to-edge coordinates, so no manual inset adjustment is appropriate.                                                           |
| Refs / imperative behavior           | **VERIFIED: NO CHANGE REQUIRED** | Refs use public `Pressable` element types or capability checks. RN 0.82's DOM-like host refs retain legacy measurement methods. No `findNodeHandle` or private host instance is used.                                                                           |
| Pressable and event semantics        | **VERIFIED: NO CHANGE REQUIRED** | Surface uses public `onPress`, hover, focus, and pressed-state contracts. It does not use hidden React `Activity` boundaries or depend on listener teardown behavior.                                                                                           |
| StyleSheet behavior                  | **VERIFIED: NO CHANGE REQUIRED** | Surface does not use the removed `absoluteFillObject` API or depend on StyleSheet numeric IDs. RN Web acceptance exercises flattened emitted styles.                                                                                                            |
| Safe-area / edge-to-edge interaction | **CHANGE REQUIRED**              | `react-native-safe-area-context` is aligned to `~5.7.0`. `AppBar` consumes `SafeAreaInsetsContext`; application roots still own the provider and Android edge-to-edge configuration.                                                                            |
| Native rendering                     | **CHANGE REQUIRED**              | The Expo icon namespace is replaced by four scoped RNVI static packages. Consumers must embed/register those fonts and rebuild native clients; Surface performs no runtime Expo font loading.                                                                   |
| React Native Web rendering           | **CHANGE REQUIRED**              | RN Web is now an explicit `~0.21.0` peer/dev baseline. Web `pointerEvents` moves to `style` while native retains the host prop. Static render and hydration acceptance covers `Container`, `ScrollArea`, `Grid`, and `Show`; icon markup is covered separately. |
| Metro / module resolution            | **CHANGE REQUIRED**              | Icon imports use published `@react-native-vector-icons/*/static` export maps. Surface adds no Metro alias, resolver override, or Expo module-resolution behavior.                                                                                               |

## Native acceptance boundary

This repository has no `ios/` or `android/` application, so it can validate component behavior and public native typings but cannot prove font embedding in a device binary. ZORA/Studio's Expo 57 development-client step must register the four RNVI config plugins, rebuild Android and iOS clients, and visually verify representative Ionicons and OAuth brand icons. That is downstream acceptance, not a Surface implementation blocker.
